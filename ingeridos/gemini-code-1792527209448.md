# Lógica de Cálculo e Ranqueamento da Listagem (Technical Spec para IA)

Este documento define a estrutura algorítmica para a busca e ordenação da listagem de Artistas. O objetivo é fornecer uma especificação técnica clara para que agentes de IA (como Aider/Cursor) compreendam as regras de extração de dados do banco e a estrutura de ordenação esperada, garantindo que usuários pagantes e não pagantes coexistam na mesma lista e sejam submetidos às mesmas lógicas matemáticas de pontuação e desempate.

## 1. Estrutura de Coleta de Dados (Input/Database)
Para que o algoritmo funcione, a query inicial no banco de dados deve coletar os perfis e calcular os seguintes campos dinâmicos para cada Artista que passar no **Filtro Base** (Match exato de Região + Todas as Especialidades solicitadas + Disponibilidade de Data/Hora)[cite: 2, 3, 4]:

*   `is_following`: Booleano (O cliente logado já segue este Artista no "Acampamento"?)[cite: 2, 3, 4].
*   `has_plano_imediato`: Booleano (Ativou o plano para fura-fila ou é Novo Usuário nos primeiros 3 dias?)[cite: 2, 3, 4].
*   `has_plano_listagem`: Booleano (Assinante do plano premium padrão?)[cite: 2, 3, 4].
*   `pontos_avulsos`: Inteiro (Soma de pacotes de pontos comprados de 100 em 100)[cite: 1, 3, 4].
*   `avaliacao_media`: Float (Nota média de 0.0 a 5.0)[cite: 2, 3, 4].
*   `total_avaliacoes`: Inteiro (Volume total de reviews recebidos)[cite: 1, 2, 3, 4].
*   `taxa_cancelamento`: Float (Percentual de furos do Artista)[cite: 1, 2, 3, 4].
*   `distancia_metros`: Inteiro (Cálculo geoespacial da distância até o cliente)[cite: 1, 2, 3, 4].
*   `proximo_horario_livre`: Timestamp (Para ordenação de urgência)[cite: 2, 3, 4].

## 2. Motor de Cálculo de Pontos (Score System)
Tanto os pagantes quanto os não pagantes habitam a mesma lista e passam pela mesma função de cálculo de pontuação (`Total Score`)[cite: 1]. A segregação natural (pagantes no topo) ocorre puramente pela injeção matemática de pontos do plano[cite: 1]:

**Fórmula Base:**
1.  **Plano de Listagem:** Se `has_plano_listagem == true`, soma-se `10.000` pontos. Se `false`, soma-se `0`[cite: 2, 3, 4]. *(É isso que garante matematicamente que pagantes fiquem no topo da lista geral, mas ainda competindo entre si pelas mesmas regras)*.
2.  **Nota (Avaliações):** Multiplica-se a média por 1.000 (ex: Nota 4.8 = `4.800` pontos. Máximo de `5.000`)[cite: 2, 3, 4].
3.  **Pontos Avulsos:** Soma-se o valor exato de `pontos_avulsos`[cite: 2, 3, 4].
4.  **Penalidade de Cancelamento:** Se `total_avaliacoes >= 50` (amostragem mínima segura), subtrai-se da pontuação a exata `taxa_cancelamento` em percentual[cite: 2, 3, 4]. *(Ex: Se tem 14.800 pontos e 10% de cancelamento, perde 1.480 pontos)*.

## 3. Estrutura de Ordenação (Sort Output)
A resposta da API deve ordenar o Array de Artistas aplicando uma arquitetura de prioridade estrita, onde a regra superior anula as inferiores:

*   **Prioridade 0 (Acampamento / Fura-Fila Absoluto):**
    *   Ordena primeiro todos onde `is_following == true`[cite: 2, 3, 4].
*   **Prioridade 1 (Urgência / Plano Imediato):**
    *   Ordena em seguida todos onde `has_plano_imediato == true`[cite: 2, 3, 4].
    *   *Ordenação interna:* Os pagantes reais do Imediato vêm acima dos "Novos Usuários" (que têm 3 dias grátis)[cite: 2, 3, 4]. Ambos ordenados de forma crescente pelo `proximo_horario_livre`[cite: 1, 2, 3, 4].
*   **Prioridade 2 (Lista Geral - Pagantes e Não Pagantes):**
    *   Ordena do maior para o menor com base no cálculo do `Total Score` (que já eleva os usuários do Plano de Listagem ao topo naturalmente pelos 10.000 pontos base)[cite: 1, 2, 3, 4].

## 4. Algoritmo de Desempate (Cascata Final)
Caso dois ou mais perfis (pagantes ou não pagantes) apresentem o exato mesmo `Total Score`, a IA deve aplicar a seguinte cascata rigorosa no banco de dados:

1.  **Geolocalização:** Menor `distancia_metros` passa à frente[cite: 1, 2, 3, 4].
2.  **Volume Absoluto:** Maior `total_avaliacoes` passa à frente[cite: 1, 2, 3, 4].
3.  **Randomização (Shuffle):** Aplicação de randomização por sessão/query (`ORDER BY RAND()` ou equivalente) para evitar privilégio a IDs mais antigos no banco caso os critérios anteriores empatem[cite: 1, 2, 3, 4].
