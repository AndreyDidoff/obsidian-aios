# Divisão Arquitetural: Atomic Design e Clean Architecture

A estrutura de repositórios do ecossistema WeCareU foi desenhada aplicando rigorosamente os padrões de **Atomic Design** e **Clean Architecture**[cite: 4]. Essa abordagem visa garantir o isolamento, a reutilização de código e a escalabilidade transversal entre as diferentes aplicações da plataforma (ui-client, ui-worker, web-admin, etc.)[cite: 1, 4].

Para evitar gargalos de dependência e manter a pureza dos componentes visuais, a infraestrutura front-end foi dividida em dois monorepos distintos, conforme ilustrado e validado nas definições arquiteturais[cite: 1, 4]:

## 1. library-design-system (Átomos e Moléculas)
Este repositório atua como a fundação visual da WeCareU (LyraUI), isolando os elementos visuais puros e agnósticos de regras de negócio complexas[cite: 1, 4].
*   **Papel:** Monorepo exclusivo para componentes menores e atômicos[cite: 4].
*   **O que abriga:** Botões, inputs, selects, tipografia (textos), tokens de design (espaçamentos, cores, bordas) e a infraestrutura de temas (theme)[cite: 1, 4].
*   **Objetivo:** Fornecer os blocos de construção básicos que serão consumidos por todos os outros repositórios, garantindo a consistência visual em qualquer plataforma[cite: 1, 4].

## 2. library-components (Organismos e Templates)
Este repositório é projetado para escalar a lógica de interface, unindo os "átomos" do design system em blocos funcionais robustos[cite: 1, 4].
*   **Papel:** Monorepo destinado a componentes maiores e estruturais[cite: 4].
*   **O que abriga:** Contextos (states), formulários inteiros, fluxos de navegação compartilháveis (ex: Auth Flow) e estruturas que englobam regras de interação mais densas[cite: 1, 4].
*   **Objetivo:** Centralizar blocos de interface e lógicas que podem ser reutilizados de forma idêntica entre os múltiplos aplicativos do ecossistema, reduzindo a duplicação de código nas camadas finais dos apps[cite: 1, 4].
